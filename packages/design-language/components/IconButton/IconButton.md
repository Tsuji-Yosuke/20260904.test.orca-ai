# IconButton

## Guide

### Purpose

- アイコンのみで意味が通じる操作のためのトリガー要素。
- ツールバーやフローティング操作など、視覚スペースが限られた面で操作を最小の面積で提供する責務を持つ。
- アイコンに紐づく「行為」を実行することに集中し、ページ遷移そのものは扱わない。
- Icon コンポーネント自体は本コンポーネントの責務外（Icon の供給・選定は呼び出し側）。

### Usage

**Use when**

- ツールバー、テーブル行、リストアイテム、フローティング操作など密度の高い文脈での操作。
- 閉じる、メニューを開く、再生 / 一時停止、削除、追加など、慣用的アイコンで意味が成立する操作。
- Button のテキストラベルを置く余白が無く、かつアイコンだけで誤解されない場面。

**Do not use when**

- アイコンの意味が文脈で一意に決まらないとき（テキスト付きの Button を使う）。
- ラベル付きの主アクション（Button を使う）。
- トグル選択肢の集合表現（Chips / SegmentedControl 等を使う）。
- URL 遷移そのものが目的のとき（リンク系を使う）。

### User Mental Model

- 「アイコン＝1 つの操作」と理解できる、コンパクトな押下対象。
- 触ると押せると分かり、押すと文脈内で結果が起きると期待できる。
- 隣接する IconButton 群は並列の操作セットとして読まれる。
- 形状（角丸矩形 / 円形）の違いは、配置文脈の違い（組み込み型 / フローティング型）として読まれる。

### Anatomy

- 必須: Container と Icon。
- Icon は Container の中心に配置する。
- 角丸矩形と円形の 2 種の Container 形状を持つ。
- テキスト Label を内包しない。
- バッジ等の付随表現は本コンポーネントの直接の構成要素にしない（必要なら別コンポーネントで重ねる）。

### Content Model

- Icon は 1 つだけ。複数のアイコンを並べない。
- アイコンの形状や大きさは密度ごとに一貫性を保つ。
- 動的に意味が変わるトグル的用途は本コンポーネントの責務外とする。

### Layout And Density

- Container は密度ごとに一貫した正方形（角丸矩形）または円形。
- Container の最小寸法は 40px（Figma の Size 軸は 40 / 48 / 56px の 3 段階）。
  40px はタッチターゲットの下限であり、これ未満の小型アイコン操作
  （例: 一覧内の 24px のお気に入りトグル）は本コンポーネントの範囲外とする。
  必要な場合は利用側で自作する（`docs/registry.md` の手順を参照。issue #48）。
- 連続して並べる場合は、隣接する IconButton 同士が誤タップされない最小間隔を保つ。
- 円形バリアントはフローティング配置（画面に対し独立して浮く操作）を想定する密度配置を取る。

### Accessibility Notes

- WAI-ARIA Button Pattern に準拠。
- **アクセシブルネームを必ず提供する**。視覚ラベルが存在しないため、Foundations 6 の必須要件を本コンポーネントでは実装上の絶対条件として強制する。
- ホバー時のみツールチップでラベルを補うのは可。ただしアクセシブルネームの代替にはしない。

## Spec

### Interaction Model

- Foundations の共通要件に準拠。固有の追加なし。

### State Model

- トグル動作（選択状態を持つ用途）は本コンポーネントの責務に含めない。
  Figma の component set にも on/off を保持する軸は存在しない（Pressed は押下中の一時状態）。
  お気に入り・ピン留めのようなトグル操作は利用側で自作する（`docs/registry.md` の手順を参照）。
  複数プロダクトでニーズが揃ったら、共通部品としての追加を再検討する（issue #48）。

### Visual Semantics

- 視覚的重みは 3 段階あり、Button と同じく操作の重要度に応じて使い分ける。
  - 強い視覚重み: 周囲から独立した強調操作（フローティング操作、空状態のプライマリ操作など）。
  - 中間の視覚重み: 輪郭で示す副次操作。並置に耐える。
  - 弱い視覚重み: 背景も輪郭も持たない補助操作。ツールバーやインライン操作に使う。
- 形状（角丸矩形 / 円形）は意味の差を持つ:
  - 角丸矩形は他の UI と並置されることを前提とした「組み込み型」の操作。
  - 円形は周囲から独立した「単体・浮遊型」の操作（フローティング配置）。

### Variants And Options

- 視覚的重みのバリアント（3 段階、意味で語る）:
  - 強調操作用（背景塗りベース、周囲から独立して強い）。
  - 副次操作用（輪郭ベース、並置可能）。
  - 補助操作用（背景・輪郭なし、密度の高い面で使う）。
- 形状バリアント:
  - 角丸矩形（既定）。他の UI と並置することを前提とする。
  - 円形。フローティング操作向け。
- Figma の `Filled` / `Outlined` / `Ghost` / `Circle` のうち前 3 つは視覚的重み 3 段階に、`Circle` は形状バリアントに対応する。ドキュメント・レビューでは必ず意味で議論する。

### Open Questions

- 危険系（destructive）の視覚バリアントの要否。
- バッジ重ね合わせの公式サポート可否。

### Acceptance Criteria

- AC-IconButton-01: Container と Icon のみで構成され、テキスト Label を内包しない。
- AC-IconButton-02: 必ずアクセシブルネームを提供する仕様であり、提供されない実装は不正とする。
- AC-IconButton-03: 視覚的重み 3 段階（強調 / 副次 / 補助）を意味として区別できる。
- AC-IconButton-04: 形状 2 種（角丸矩形 / 円形）を意味として区別でき、円形はフローティング配置を想定する。
- AC-IconButton-05: トグル動作を持たず、選択状態は表現しない。
- AC-IconButton-06: 連続配置時に隣接する IconButton 同士が誤タップされない最小間隔を維持する。（検証: Storybook）
- AC-IconButton-07: Foundations (`principles.md` / `accessibility.md`) の共通要件をすべて満たす。（検証: Foundations）
